# Итерация 4: Мини-карта-память с маркерами клада + локальная таблица рекордов

## Заголовок
Добавить две независимые, дешёвые механики: (1) **карту-память игрока** — постоянную мини-карту изученных клеток + ручные маркеры «клада здесь / не здесь», которые игрок ставит сам (клавиша и клик), не раскрывая туман дальше радиуса 1; и (2) **локальную таблицу рекордов** по уровням через `localStorage`, дающую мета-цель.

## Мотивация
Главная боль итераций 0–3 — блуждание вслепую: туман всегда радиус 1, и разведанное снова прячется. Игрок запоминает карту только в голове, ошибается и впустую ходит кругами. В бумажной версии можно было рисовать; сейчас этой возможности нет. Самое ценное дополнение — дать игроку **его собственную карту-память**: клетки, которые он уже разведал на этой партии, остаются навсегда видимыми в мини-области (они уже реально посещены — это не расширение тумана, а вечный разведданные игрока). Плюс ручные маркеры позволяют помечать «тут точно был сундук / тут его нет» — делая исследование осмысленным.

Приоритизация (effect/стоимость): карта-память закрывает главную боль при минимальном коде (переиспользуем существующий рендер клеток, добавляем один «когда-либо посещённый» массив + слой отрисовки вне видимой зоны). Рекорды — почти бесплатны (несколько строк, `localStorage`), добавляют мета-цель и переиграбельность. Вместе закрывают «почему блуждать» и «зачем дальше играть». Новые объекты (ключ/болото/окно) отложены — они дороги и меняют баланс. Обучение отложено — управление простое, подсказки уже есть в статусе/log.

## Конкретное ТЗ

### 1. Карта-память разведанных клеток
**Суть:** клетка, на которой игрок уже был (или которая была видима), остаётся навсегда разведанной для него на текущей партии. Это НЕ изменяет туман (`visible`), не открывает ничего нового дальше радиуса 1 — просто хранит историю и отображает её вне активной зоны.

#### 1.1 Состояние
В блок «Состояние» добавить:
```js
let explored = Array.from({length:H},()=>Array(W).fill(false)); // никогда-разведанное
let markers = {}; // ключ "r,c" => тип маркера ('q' вопрос / 'x' не здесь / 'chest' клад тут)
```
- `explored` — матрица `H×W`, изначально все `false`. `init()` создаёт её заново (сброс на новую партию).
- `markers` — объект (assoc) вместо массива для простоты: ключ `"r,c"` → тип маркера. Тоже сбрасывается в `init()`.

#### 1.2 Заполнение при каждом входе в клетку
В `tryMove` (после успешного шага, до `bearTurn`) и в начале `init()` (отметить стартовую клетку) пометить окрестность радиуса 1 как разведанную. Ввести хелпер:
```js
function markExplored(){ // окрестность радиуса 1 вокруг игрока
  for(let dr=-1;dr<=1;dr++)for(let dc=-1;dc<=1;dc++){
    const r=player[0]+dr, c=player[1]+dc;
    if(r>=0&&r<H&&c>=0&&c<W) explored[r][c]=true;
  }
}
```
Вызывать `markExplored()`:
- в `init()` сразу после установки `player` (до первого рендера),
- в `tryMove` после `player = [r+dr,c+dc]`,
- в `riverJump` и ветке `holes` в `onEnter` (после телепорта) — чтобы карта фиксировала новую позицию даже при резком переносе.

> Почему «радиус 1», а не только клетка игрока: клетка игрока всегда видна, но соседи по краю 3x3 видны при заходе. Отмечать весь квадрат 3x3 — дёшево и совпадает с тем, что игрок реально видел. Отмечать «только посещённую» клетку тоже допустимо, но тогда карта скуднее; квадрат 3x3 — разумный компромисс.

#### 1.3 Отрисовка карты-памяти
В `render()`, ДО цикла активной (видимой) зоны, нарисовать разведанные клетки за пределами текущего экрана, но **только те, что в пределах одного-двух шагов от экрана** — чтобы не засорять кадр. Простая схема: использовать существующие `sx/sc` (масштаб уже world-привязан к камере) и для каждой клетки `explored[r][c]===true`, которая НЕ `visible(r,c)` и попадает в прямоугольник канваса, закрасить фон угасающим цветом и нарисовать маркер, если есть.

Алгоритм:
```js
// слой карты-памяти (затемнённые разведанные клетки вне активной зоны)
for(let r=0;r<H;r++)for(let c=0;c<W;c++){
  if(!explored[r][c] || visible(r,c)) continue;
  const x=sc(c), y=sx(r);
  if(x<-CS||x>N||y<-CS||y>N) continue; // вне экрана — пропуск
  ctx.fillStyle='rgba(38,42,52,.35)'; ctx.fillRect(x,y,CS,CS);
  ctx.strokeStyle='rgba(255,255,255,.05)'; ctx.lineWidth=1; ctx.strokeRect(x,y,CS,CS);
  const m = markers[r+','+c]; // маркер, если поставлен
  if(m) drawEmoji(m==='q'?'❔':m==='x'?'❌':'💎', x+CS/2, y+CS/2, 24);
}
```
- Цвет затемнённого фона `rgba(38,42,52,.35)` — «разведано, но активно скрыто туманом». Рисовать маркер крупнее/ярче, чем фона, но меньше активных эмодзи (24 vs 30).
- Если клетка одновременно `visible` — её рисует основной цикл (маркер там тоже может показываться, см. 1.4), слой карты её пропускает (`continue`).

#### 1.4 Маркеры на активных клетках
Если игрок поставил маркер на клетке, которая сейчас видима, показывать его маленьким значком поверх (в углу клетки), не путая с содержимым:
```js
// в основном цикле видимых клеток, после drawEmoji содержимого:
const m = markers[r+','+c];
if(m) drawEmoji(m==='q'?'❔':m==='x'?'❌':'💎', x+CS-12, y+12, 14); // маленький в углу
```

#### 1.5 Управление маркерами — клавиша и клик
- **Клавиша `M` (или `E`):** циклически переключает маркер на клетке игрока: `нет → 'q' (❔) → 'x' (❌) → нет`. Переключение одной клавишей — самое дешлое и предсказуемое.
- **Клик мыши по канвасу:** поставить/переключить маркер на клетке под курсором, если она `explored` (иначе — сообщение «Сначала разведай эту клетку», без действия). Преобразование экран→мир:
```js
function cellFromMouse(e){
  const rect = cv.getBoundingClientRect();
  const mx = (e.clientX-rect.left)*N/rect.width;
  const my = (e.clientY-rect.top)*N/rect.height;
  // обратные к sx/sc: c = drawC + (mx-C)/CS, r = drawR + (my-C)/CS
  return [Math.round(drawR + (my-C)/CS), Math.round(drawC + (mx-C)/CS)];
}
```
  где `drawR/drawC` — те же, что в `render()` (нужны вычисляемые внутри функции; при `moving=false` это `player`).
- Обработчик `cv.addEventListener('click', ...)` (поставить после создания `cv`), игнорировать при `over` и когда кликают вне поля или на неразведанную клетку.
- Логика циклического переключения — общая функция:
```js
function cycleMarker(cell){
  const k = cell[0]+','+cell[1];
  const cur = markers[k];
  markers[k] = cur ? (cur==='q' ? 'x' : undefined) : 'q';
  // 'q' -> 'x' -> снято -> 'q'
  if(markers[k]===undefined) delete markers[k];
  sfx('aim'); // короткий пик-подтверждение
}
```
  (Если хочется ещё маркер «💎 тут клад», расширить цепочку: `없 → 'q' → 'x' → 'chest' → 없`; но минимально достаточно `q/x`.)

> Заметка о «кладе»: сундук — подвижная цель (при ранении падает в другую клетку). Маркер «💎 тут клад» может устареть. Поэтому в базовой версии — только `❔`(не уверен) и `❌`(`точно не здесь`). Маркеры — заметки игрока, а не живой статус; они не обновляются автоматически.

#### 1.6 Легенда
В `#legend` добавить две записи: `❔ — сомнение` и `❌ — клада нет`, и в нижней строке — подсказку: `<span class="k">M</span> — пометить · клик — пометить клетку`.

### 2. Локальная таблица рекордов (localStorage)
Мета-цель: лучший результат по достигнутому уровню и времени. Храним **лучший пройденный уровень** и **лучшее время на уровень 1** (простой, понятный метрикой).

#### 2.1 Хранилище
Ключ `labyrinth.best`. Значение — JSON:
```js
{ level: 0, time1: null } // level: наивысший пройденный уровень; time1: лучшее время (с) на уровень 1
```
Не глобальный синглтон — реализовать через маленькие функции-хелперы с `try/catch` (при недоступности localStorage игра работает без него).

#### 2.2 Обновление при событии
- **В `endWin`**: `level` уже увеличен на 1. Сравнить с сохранённым рекордом: если новый пройденный уровень (`level - 1 < 0 ? 1 : level - 1` — фактически «level до инкремента») больше сохранённого — обновить `best.level`. Для уровня 1 записать `time1 = min(сохранённый, LEVEL_TIME - timeLeft)`.
  ```js
  function saveBest(){
    const passed = level-1; // номер пройденного уровня (до ++ в endWin)
    const t = LEVEL_TIME - timeLeft;
    let b = loadBest();
    if(passed > b.level) b.level = passed;
    if(passed === 1 && (b.time1===null || t < b.time1)) b.time1 = t;
    try{ localStorage.setItem('labyrinth.best', JSON.stringify(b)); }catch(_){}
  }
  ```
- **В `endLose` / `endTimeout`**: результат уровня не засчитывается; ничего не менять (уровень сбрасывается, но рекорд пройденных должен остаться — это «личный лучший», а не текущий прогресс).

#### 2.3 Отображение рекорда в overlay и под HUD
- В overlay-панель рекордов не обязательно — но полезно показывать в `endWin`: строка `Рекорд: уровень <b>N</b> · лучшее время L1 <b>Ts</b>с` если есть. Добавить через `showOverlay(..., statsHtml)` — встроить `<br>Рекорд: ...`.
- Под HUD (в `<h1>` или отдельной строке `#bestline`) показать текущий личный рекорд при инициализации и обновлять при победе.
  Минимально: отдельный `<div id="bestline" style="font-size:12px;color:#9aa0ab;">Рекорд: уровень 1 · 20.0с</div>` между `h1` и `status` (или под `.hud`). Обновлять в `updateHUD()` или при `init()`.

#### 2.4 lazy-загрузка
При `init()` прочитать рекорд один раз и отобразить в `#bestline`. Хелперы:
```js
function loadBest(){ try{ const v=localStorage.getItem('labyrinth.best'); return v?JSON.parse(v):{level:0,time1:null}; }catch(_){ return {level:0,time1:null}; } }
```

### 3. HTML/CSS
- Добавить небольшой блок рекорда `#bestline` (2–3 строки CSS, стиль как у `#log`).
- В `#legend` добавляются записи про маркеры (`❔`, `❌`) и подсказку клавиши `M`/клика.
- Кнопки/overlay/HUD не меняются.

## Что нельзя трогать (регрессионная защита)
- **Туман** `visible(r,c)`: по-прежнему видна только зона радиуса 1 от игрока. Карта-память `explored` НЕ участвует в `visible` — она влияет только на отдельный слой отрисовки и маркеры. НИ ОДНА клетка дальше радиуса 1 не становится «активно видимой» — всё новое, что появляется, это либо ранее посещённая (уже честно виденная) клетка, либо ручной маркер игрока. Строго не нарушать требование «не расширять туман дальше радиуса 1».
- **Вся игровая логика**: `genWalls`, `ensureConnected`, `tryMove` (кроме вызова `markExplored`), `bearTurn`, `bomb`/`aiming`, река, дырки, арсенал, госпиталь, ловушки, сундук, выход, `endWin/endLose/endTimeout`, таймер, уровни, HUD, компас, пульс-стрелка, звук `sfx`, анимация `frame`/`camR/camC`, клавиши движения — без изменений.
- **Рендер активной зоны** и его порядок (клетки → стены → медведи → игрок → пульс) не переписывается; добавляются только два ОТДЕЛЬНЫХ слоя: карта-память (до активного цикла) и маленькие маркеры в углу клеток.
- **Overlay** и кнопки/клавиши рестарта не меняются; к overlay только добавляется строка рекорда при победе.
- Минимальное число новых зависимостей: 0. Всё на чистом JS + canvas + клавиатура (+ мышь-клик для маркеров, допустимо как уже существующий HTML-инпут).

## Критерий приёмки
1. **Карта-память**: после первого хода клетки, в которых игрок побывал (окрестность радиуса 1), навсегда остаются видны на канвасе как затемнённые. При уходе в другую часть лабиринта разведанные клетки не исчезают (в отличие от тумана активной зоны). Клетки, никогда не посещённые, остаются полностью скрытыми.
2. **Туман не расширен**: функция `visible(r,c)` даёт ровно тот же радиус 1, что и в итерации 3; ни одна неразведанная клетка не показывается. Отличие — только слой «побывал» и маркеры.
3. **Маркеры**: клавиша `M` на клетке игрока ставит `❔`, повторно — `❌`, в третий раз — снимает. Клик по разведанной клетке ставит/снимает маркер; клик по неразведанной клетке показывает сообщение и не ставит маркер. Маркеры отображаются на канвасе (маленькие в углу на активных клетках, крупнее на карте-памяти) и после перезахода на клетку сохраняются до конца партии.
4. **Маркеры не «живы»**: маркер `❌` остаётся, даже если там реально есть клад/выход — это заметки игрока, авто-обновления нет.
5. **Рекорды**: первая в сессии победа на уровне 1 записывает время; лучшее время сохраняется между перезагрузками страницы. Победа на более высоком уровне поднимает рекордный уровень. Поражение/таймаут не портят сохранённый рекорд (сбрасывается только текущий `level`, а не «лично лучший»).
6. **Рекорд отображается**: строка рекорда (уровень и лучшее время L1) видна на странице и обновляется при новой победе.
7. **Регрессия**: движение, анимация, звук, бомбы, медведи, таймер, уровни, overlay, рестарт (R/кнопка/кнопка overlay) работают как в итерации 3. localStorage без прав (br/private browsing / отключено) не ломает игру — она работает без сохранения рекорда.

## Риски
- **Производительность слоя карты**: перебор всех 100 клеток каждый кадр — дёшево, но добавляется к уже постоянному `requestAnimationFrame`. Ограничение «только вне экрана` (`x<-CS||x>N||... continue`) держит отрисовку малой; при необходимости можно ввести привязку к видимой области через камеру. Пока не требуется.
- **Клик-маркеры против существующего UI**: клик на канвас не должен конфликтовать с другими обработчиками; канвас в текущем коде не имеет обработчиков кликов — добавить один отдельный, не трогая `keydown`.
- **Река/дырка телепортируют резко**: `markExplored()` вызовется в `riverJump`/ветке `holes` — важно, чтобы телепорт не «прыгал» камерой на неразведанные клетки. После телепорта отмеченная окрестность соответствует новой позиции игрока — корректно.
- **Маркеры и `drawR/drawC`**: вычисление клетки под курсором требует тех же `drawR/drawC`, что в `render()`. При `moving` надо аккуратно получать текущую draw-позицию (рассчитывать из `animFrom`+`e`, как в `render`). Во избежание рассинхрона вынести расчёт draw-позиции в отдельную функцию, используемую и в `render`, и в `cellFromMouse`.
